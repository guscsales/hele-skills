# Execution Plan — Deliver small changes directly

<objective>
After this increment the shipped contract delivers a Bugfix, a Fast addition or a correction of the active increment through a direct path: one owning engineer investigates, proves the change with the smallest failing test, runs only the checks that reach the changed files, and the conductor closes with evidence and the rule delta. No increment, no execution plan, no Beads issues, no separate review, no QA phase. The conductor sends work to the full path only when the ask itself names an excluded surface; otherwise the engineer decides and escalates with findings. On both paths a failing check the change does not reach is recorded as pre-existing instead of becoming triage, an unexplained reached failure stops for the human's two-choice decision, and no previous-revision comparison (worktree, dependency install, second environment) is ever ordered unless the human chose it for this delivery. Covered rules: BR-22, BR-23, BR-24, BR-25 and the rewritten BR-2, BR-4, BR-8, BR-9, BR-11, BR-12, BR-13.
</objective>

<approach>
One shared contract, `templates/direct-path.md`, modeled on `templates/build-until-pass.md`: a `<conductor>` block (entry, dispatch, Wylie calls, the two stops, the close) and a `<worker>` block (the engineer's numbered contract, modeled on hele-tweak phase 2). The conductor, the Fast/Bugfix skill and the adjust phase each route to it with one paragraph instead of restating it, so the rule text exists once and the routing points can be tested independently. A new `skills/hele-direct/` was rejected: BR-11 says the direct path is not a lane, and a skill would add a phase name to `sticky-lanes.md`, `ai.js` and `.docs/` for no behavior.

Decisions inside the PRD's room, so the engineers do not have to make them:
- Excluded surfaces (BR-22, glossary) are listed verbatim in `templates/direct-path.md` and referenced, not copied, from the conductor.
- Conductor pre-escalates only when the human's words name an excluded surface (TS-041); otherwise it dispatches the owning engineer (Cho for server/CLI/contracts, Van Pelt for UI) with model from `settings.agents.models` (TS-042).
- Rule handling before dispatch (BR-2): unchanged rule → no PRD touch, no stop (TS-045); rule fully decided by the human's words → Lisbon patches the PRD (patch bump + changelog) in session and dispatches without a stop (TS-046); product doubt → Question pack, nothing written (TS-047).
- When a rule changed, Wylie (`qa-wylie-stubs`, hele-stubs contract) is dispatched in the same turn as the engineer; the close waits for both (TS-063). No rule change → Wylie is not called (TS-064).
- Worker exits: `DONE` (proof fail→pass, related checks, not run and why, pre-existing failures with name + error excerpt), `ESCALATE` (excluded surface found; stop, keep partial work, findings), `UNEXPLAINED` (a reached check fails and he cannot explain it; leave the change in place, return the check, excerpt and two time estimates or `unknown`).
- `UNEXPLAINED` → conductor prints the two-choice stop and calls nobody (TS-055). Choice continue → recorded pre-existing, close. Choice compare → Wylie (`qa-wylie-run`) compares that one check against the previous revision, closed scope.
- A needed real journey (BR-23 case 1) is flagged by the engineer in his report; the conductor dispatches Wylie (`qa-wylie-run`) for that journey only (TS-052). Otherwise no Wylie run (TS-051).
- `ESCALATE` → conductor announces the escalation with its reason, then runs `hele-fast` on the full path; the engineer's findings are passed to `hele-plan` as `<current-state>` input (TS-043, TS-044).
- Correction of the active increment on the direct path (BR-13): the engineer, in the same dispatch, sets the touched flow in `VERIFY.md` to `pending` and rewrites its expected result from the corrected rule; plan and QA report are untouched; the close returns to `hele-verify-work` for that flow only (TS-060). Giving the engineer this one edit (like Tweak's quote sync) avoids calling Wylie outside the two BR-23 cases.
- BR-24 on the full path: `hele-build` final checks record unreached failures as pre-existing and do not route them; a reached unexplained failure uses the same two-choice stop. The prohibition on unordered previous-revision comparisons is written in three places the conductor composes prompts from: `skills/hele/SKILL.md` rules, `skills/hele-build/SKILL.md` phase 2, `skills/hele-qa/SKILL.md` phase 3 dispatch; plus Wylie's `<never>`. How a pre-existing failure appears inside a QA_REPORT is left to `behavior-validation`.

Staffing. All contract text and CLI work is Cho's (server-side/CLI owner in this repo, as in prior harness changes); the human-facing chat shapes in `templates/chat-reports.md` are the product's UI and go to Van Pelt. No Jane (no auth, permissions, payments or PII touched), no Hightower (no schema), no Rigsby (CI unchanged; new test files match the existing `test/*.test.js` glob), no Vega (see `<out-of-plan>`).

Deviation from Wylie's Coverage recommendation: he proposed one file, `cli/test/direct-path.test.js`. The proof is split into `cli/test/direct-path.test.js` (T1, then T5 appends after T1 closes), `cli/test/direct-path-routing.test.js` (T2), `cli/test/direct-path-build.test.js` (T3) and `cli/test/direct-path-reports.test.js` (T4). Same level (contract text), same runner, same `npm test` job, same assertions as his rows. The runtime replay row stays proposed and is not built here.

This is not a release: nothing is tagged, pushed or published. It is included because CI's `version` job fails any PR without it and every earlier feature change carried its own minor bump; if the human chooses no PR at the close, the bump stays in the uncommitted tree with the rest.
</approach>
