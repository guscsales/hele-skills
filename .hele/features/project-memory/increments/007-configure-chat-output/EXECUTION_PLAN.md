# Execution Plan — Configure chat output

<objective>
After this increment a project chooses how much of each report appears in the conversation through `.hele/settings.json` `output`: a preset (`compact` default, `standard`, `detailed`), `tables`, `maxTableRows` and six section values (`testStubs`, `coverage`, `prdDelta`, `qaResults`, `dispatch`, `screenshots`). The CLI validates every write under `output` (exit 1, file byte-identical on refusal), prints the one effective resolution with `hele config effective output` (works without `.hele/` or without `settings.json`, never writes, `warnings` array for hand-edited invalid values), and removes any saved key with `hele config unset`. `core/default-config.json` and init save only `output.preset: "compact"`. The shared chat contract (`templates/chat-reports.md`) and every skill and agent that presents a report take their presentation from that one resolution: section levels, omission lines with counts and a way to expand, expansion that only re-presents, and always-visible failures, blockers, missing required coverage, questions, decisions, options and walk steps that no setting and no one-off request can hide or cut. Documents, evidence, tests, approvals and workflow stages are unchanged under every setting. Covered rules: project-memory BR-18–BR-26 and rewritten BR-5, BR-6; guided-delivery rewritten BR-18; product-absorption rewritten BR-15. Ships as plugin v1.8.0.
</objective>

<approach>
One resolver in the CLI, one presentation contract in `templates/chat-reports.md`, every consumer pointing at both. The CLI is the only place that knows preset values and the plugin default; the chat contract is the only place that knows how a section level renders; skills and agents name the section and point at the command, never carry a number or a default of their own (BR-19). This beats the alternatives: preset values in `core/default-config.json` would be copied into every reinitialized project by hele-init and become overrides (BR-25 hazard above); preset values in `chat-reports.md` would make agents compute the resolution themselves and drift from the CLI.

CLI shape (T1):
- New module `cli/src/output.js`: `PLUGIN_DEFAULT_PRESET = 'compact'`; `OUTPUT_PRESETS` (the BR-21 table, literal); `OUTPUT_KEYS` (allowed values per BR-18); `validateOutputWrite(keys, value)` (validates only the path being written and its value, so an unrelated hand-edited invalid value elsewhere never blocks a valid write); `resolveEffectiveOutput(settings)` returning `{ preset, tables, maxTableRows, sections: { testStubs, coverage, prdDelta, qaResults, dispatch, screenshots }, warnings: [] }`.
- `warnings` entries are objects `{ "key": "<dot path>", "saved": <saved value>, "used": <value now in effect, or null when the key is ignored>, "reason": "invalid" | "unknown" | "not-object" }`. For a non-object at `output.sections`, `used` is the name of the preset that supplies the sections; for a non-object at `output`, `used` is `"compact"`. This is the implementation of BR-20's "naming the key and the value used instead"; the shape is not a product rule and the tests pin it.
- `hele config effective output` resolves `.hele/` with `resolveHeleDir()` (not `requireHeleDir()`), so no memory or no `settings.json` prints the `compact` defaults with exit 0 and writes nothing. `effective` with a missing path or any path other than `output` exits 2 (usage error, same class as an unsupported action). A malformed `settings.json` keeps today's behavior for every action (not changed by this increment).
- Argument checks keep their order: missing path or value → exit 2 before any `output` validation (exit 1). `add` under `output` → exit 1. `unset` applies no value validation (BR-26).

Presentation contract (T3): a new `## Output` section next to `## Language` in `templates/chat-reports.md`, plus per-block level shapes. Consumers (T4, T5) reference that section and the block names fixed below, so T4 and T5 wait for T3 and then run in parallel:
- `## Output` (section, outside `<canonical-blocks>`)
- `## Scenarios (testStubs)` replaces `## Stubs in full`
- `## Coverage recommendations (coverage)`
- `## PRD delta (prdDelta)`
- `## Test results (qaResults)`
- `## Shots (screenshots)`
- `## Dispatch announcement (dispatch)`
- `## E2E audit (chat)` (new)
- the omission line contract and the always-visible list live in `## Output`.

Staffing: this repo has no frontend. `templates/chat-reports.md` is the human-facing surface of the harness, and Van Pelt owned it in increment 006 (T4 there); she owns it again (T3) so the chat contract has one author. Cho owns the CLI, the defaults, the skill/agent consumers, docs and release: these are literal edits against a fixed contract, his strength. No Jane task: the change edits a local JSON preferences file through the user's own CLI and markdown instructions; no authentication, permission, payment, personal data, secret or network surface is touched, and refusing invalid writes reduces rather than adds risk. No Rigsby task: CI already runs every `test/*.test.js` and the stale-bundle check; nothing in `.github/workflows/ci.yml` changes. No Hightower: no database. No Vega: `designSystem.enabled` is false.
